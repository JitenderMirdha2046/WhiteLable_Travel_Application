▸ Event Flow (Async via Kafka)

Trip Service produces:
TRIP_CREATED { tripId, userId }
TRIP_REPLAN { tripId, userId, instruction }
COMPARE_REQUESTED { userId, destination }
→
Kafka
trip-events
→
AI Service consumes:
TRIP_CREATED → generate itinerary + weather + budget
TRIP_REPLAN → regenerate with instruction
COMPARE_REQUESTED → generate 3 plans (budget/luxury/adventure)
Notification consumes:
TRIP_CREATED TRIP_COMPLETED TRIP_FAILED → log notification

▸ Database Entities & Mappings

Database: travel_user_db

users
id UUID PK
name VARCHAR(100) NOT NULL
email VARCHAR(100) NOT NULL UNIQUE
password VARCHAR(255) NOT NULL
created_at DATETIME NOT NULL

Database: travel_trip_db

trips
id UUID PK
user_id UUID FK → users.id
destination VARCHAR(100) NOT NULL
budget DECIMAL(10,2) NOT NULL
days INT NOT NULL
travel_type VARCHAR(50) NOT NULL
mood_description TEXT NULL
trip_status VARCHAR(30) NULL
weather_summary TEXT NULL
cache_used BOOLEAN NULL
total_estimated_cost DECIMAL(10,2) NULL
itinerary TEXT NULL
status VARCHAR(20) NOT NULL DEFAULT 'PENDING'
created_at DATETIME NOT NULL
trip_id
trip_budget
id UUID PK
trip_id UUID FK → trips.id
hotel_cost DECIMAL(10,2)
food_cost DECIMAL(10,2)
transport_cost DECIMAL(10,2)
activity_cost DECIMAL(10,2)
misc_cost DECIMAL(10,2)
user_id
trip_comparison
id UUID PK
user_id UUID FK → users.id
destination VARCHAR(100) NOT NULL
comparison_type VARCHAR(50) NOT NULL
itinerary TEXT NULL
Note: No JPA relationship annotations used anywhere. All foreign keys are logical (plain UUID columns). Joins are done manually in application code. No cascade, no lazy/eager loading.
